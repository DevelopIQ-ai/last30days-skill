**Breaking.** The engine no longer degrades silently. `pipeline.run` refuses to start unless the caller supplies a query plan, says who is judging relevance, and covers the web lane, and it names every gap with its effect and how to close it. Previously each of these had its own fallback — a one-query deterministic planner, upvote-and-keyword ranking, an empty general-web lane — and a run could lose all three at once and still exit 0 with a report that read exactly like a good one.

Every requirement is satisfiable by the hosting agent with no API key, which is the point of the change rather than a consolation. The agent writes the plan (it always could; SKILL.md has said so since v3). `--agent-rerank` says the agent will judge relevance while synthesizing, so the engine returns a wider candidate set in retrieval order and labels it as such instead of presenting upvote order as relevance. A host that declares `LAST30DAYS_NATIVE_SEARCH=1` owns the web lane itself. An API key remains an alternative for ranking and web search, never a requirement. `--agent-rerank` defers to a configured reranking model, so an agent can pass it unconditionally without degrading a key-configured install.

The MCP `research` tool accepts a `plan` argument and declares both agent capabilities, so MCP hosts get the same planner Claude Code gets rather than the fallback the engine itself labels "the headless/cron path only". A malformed plan is a tool error naming the fault, never a silent drop to that fallback.

`--mock` is exempt: it replays fixtures and performs no inference.
