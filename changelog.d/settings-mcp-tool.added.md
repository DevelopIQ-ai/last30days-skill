Expose the settings page over MCP. The server gains a `settings` tool alongside `research` and `preflight`; it starts the local settings page and returns the URL for the model to relay, so adding an API key or toggling a source works from an MCP host without dropping to a shell.

Unlike the other tools, `settings` starts a server rather than running the engine to completion, so it spawns through a new `engine.StartBackground`, waits only for the line carrying the URL, and detaches. A tool cannot stop a process after returning, so the child always receives an idle `--timeout` (default 900 seconds) and shuts itself down; the tool reports the pid so it can be stopped sooner. `last30days settings --timeout <seconds>` exposes the same deadline on the command line, defaulting to 0 (never) for interactive use.
